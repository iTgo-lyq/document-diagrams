# 四个初始回归命题

这些命题来自 OpenFolio 的组合实验。使用对应项目源码作为事实依据，不将其业务概念写入通用 skill。原始源码基线提交为 `896fea2fda3bd79e5bf78259740be76c0eb9bded`；该源码不包含在本仓库中，需要评估者自行提供。

在独立输出目录从源码安装 `skills/document-diagrams/`，使用该目录内的入口运行以下原题，记录模型、思考强度、业务源码提交和 skill 仓库提交。运行环境不要包含本仓库的其他目录，以验证安装内容可以独立使用。不要把已有成品或下方评审关注点作为预设答案交给生成 Agent。人工评审负责核实事实与效果；具体图形类型由 Agent 选择。

## 原题

以下原题保留业务问题作为上下文。按当前 SVG 制作范围，阅读 OpenFolio 实现及相关文档，为每题制作一张中文 SVG 图，面向没有参与开发的产品和技术评审者；交付物仅为 SVG。原题中的文档叙述要求用于判断图的事实与取舍，不要求生成 Markdown 或 HTML。自行判断最适合的图表形式，不预设架构图、流程图或时序图。

01-project：OpenFolio 怎样把工程记录变成阅读入口？
请写一节项目介绍，让读者理解使用者、资料来源、关键处理环节、最终呈现，以及 OpenFolio 与外部系统的责任边界。选择一个最值得用图表达的核心关系，其他背景和解释放在正文。不要把完整模块清单都画进图中。

02-switch：切换身份时，迟到的数据会怎样？
浏览器记住了 A、B 两个身份，正在用 A 加载文档，切换到 B 后 A 的请求才返回。请写一节技术方案说明系统如何避免显示错误身份的数据，并交代切换失败时的用户状态。用图帮助读者抓住关键机制；完整失败语义、并发细节和实现依据用正文说明，不能为简洁而写出错误承诺。

03-ownership：哪些数据跟着浏览器，哪些跟着身份？
同一个人在两个浏览器里使用 OpenFolio，每个浏览器可能记住多个 token。请写一节需求与行为说明，讲清数据归属与共享边界，并解释“移除一个身份”和“退出全部设备”的影响。选择最难仅靠文字理解的关系画出来；完整操作规则可以写在正文或一个简短表格里，不把表格再塞进图形。

04-sharing：没有仓库权限的人怎样查看已推送的原型？
作者将可预览的原型提交并推送到仓库，想分享给没有仓库权限的人。以项目支持的 Git 原型路径写一节方案说明：分享前还需要什么准备、哪些阶段需要仓库权限、公开访问依赖什么。图聚焦最关键的关系或过程；运行前提、失败限制、版本与撤回语义放正文，不把当前实现与设计建议混写。

## 评审关注点

- 项目介绍：来源、处理、阅读入口与外部系统责任边界明确，没有退化为完整模块清单。
- 身份切换：能读出先后与条件；准确区分旧请求、切换成功/失败和迟到结果，不承诺实现中不存在的行为。
- 数据归属：浏览器本地与身份共享的关系清楚，操作后果由正文或表格补足。
- 原型分享：准备、权限、公开访问之间的阶段关系清楚；版本和撤回语义有依据。
- 所有题：正文与图互补；中文在约 800px 阅读宽度清晰，分组、连线和条件不会因浅色样式或紧凑布局而丢失。

可以将旧组合实验作为人工对照，但不预设新图必须复制旧图的类型或布局。之后增加其他项目和更长文档，避免只针对这四题调优。

## 语义配色与焦点回归

以下两题无需业务源码，可在隔离的 skill 安装目录运行。先给生成 Agent 题目，再用评审关注点验收。

- **多角色架构图：** Upload/API 提供输入，Parser/Worker 处理，Model 分析，Store/Report 保存和输出，Sensitive Vault 保存敏感资料。Parser 是唯一需要重点解释的节点；按给定关系绘图，不添加组件。
- **分类面积图：** 用 Marimekko 表达三个渠道、三个类别的交叉数量，明确数量表和单位。一个类别用蓝色，一个紫色类别中的单元格是焦点，其他类别也需要稳定的颜色与图例。

评审关注点：对应角色保留蓝、橙、绿、紫、粉语义色，非焦点不退成全灰；Parser 保持处理色，只增加焦点强调。蓝色类别在多列重复不计作多个焦点；紫色焦点保持类别颜色并声明 `data-focal="true"`。数量、面积、分组、连线和图形预算保持类型规则，颜色不能替代标签或关系符号。对照热力图、蜂群图和瀑布图时，仍须保留单色单调深浅、统一非焦点填充和增量填充／减量空心。
